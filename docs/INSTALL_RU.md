# Установка на телефон

Основной сценарий 0.7.0: телефон получает Telegram, ПК разбирает сообщения через подписку Claude и записывает **свою еду в твой FatSecret на эмуляторе**. FatSecret на физическом телефоне можно использовать для обычного просмотра синхронизированного дневника.

1. Установи выданный APK 0.7.0 поверх предыдущей локальной версии. Не удаляй старое приложение: так сохранятся токен, ID и настройки ПК. Test APK предназначен только для эмулятора, на телефон его не устанавливай.
2. На вкладке Telegram сохрани токен бота и свой числовой ID. Если они уже сохранены, нажми «Проверить соединение».
3. На вкладке ИИ вставь HTTPS-адрес ПК и код из личного сообщения. Включи согласие, сохрани и проверь связь.
4. На главной нажми «Запустить». Открой своего бота и напиши `/help`.
5. Пришли описание еды, фото этикетки/блюда или штрихкод с голосовым комментарием. [Примеры](ONE_MESSAGE_RU.md).

В основном маршруте не нужно включать Accessibility на физическом телефоне, оставлять открытым FatSecret, выбирать продукты из каталога или подтверждать каждую цифру. Всё заполнение выполняется на ПК в уже авторизованном эмуляторе. ПК и помощник должны работать.

Telegram принимает только настроенный приватный чат с совпадающим отправителем. Второй приёмник того же бота запускать нельзя. Пересылки и группы отвергаются. После перезагрузки/принудительной остановки телефонный агент запускается пользователем заново. На Realme разреши фоновую работу Android Agent и отключи ограничение батареи.

Фото и голос, отправленные подряд, объединяются. Без подписи фото не требует дополнительного ответа: после окна ожидания оно обрабатывается само. При отсутствии данных штрихкода приходит отказ без записи, при оценке блюда - явная пометка оценки. `/status` показывает результат последнего задания; не дублируй еду при задержке ответа.

Код привязки сохраняется. После перезапуска временного HTTPS tunnel адрес может измениться; постоянный адрес ещё не настроен. Не публикуй код, токены и личные снимки. Диагностика приложения не содержит секретов. Физический Realme, реальный микрофон, сборка нескольких медиа и межустройственная синхронизация проверяются отдельно на телефоне.

Ранее реализованный экранный поиск и developer API относятся к отдельным режимам разработки и не нужны для описанной записи своей еды.
