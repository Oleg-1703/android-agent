## 17.11.2026 - 0.9.0, ожидание с выключенным экраном

- По жалобе на фото с подписью и двухминутную тишину найдена конкретная причина: любое фото ожидало голос 150 секунд, а проверка разблокировки стояла перед отправкой ИИ. Теперь фото с подписью/соседним описанием использует окно восемь секунд. Фото без подписи сохраняет окно до 150 секунд для длинного голоса, но бот сразу объясняет ожидание и возможность выключить экран.
- ИИ получает запрос при погашенном экране. Проверенный prepared-план сохраняется зашифрованно, отдельно для подключения ПК и Telegram-владельца, до начала claim. Очередь продолжается при обычной разблокировке через работающий service, входящие cancel/stop обрабатываются первыми. `/status` читает ожидание, `/cancel` завершает планы без формы; старые неопределённые записи и квитанции не меняются. Из очереди план удаляется после устойчивого результата PhoneMealRunner; сбой удаления не повторяет исполнение.
- Экран удерживается только на время UI-транзакции, максимум 120 секунд, и освобождается в finally. Использован ограниченный SCREEN_DIM_WAKE_LOCK с нормальным разрешением WAKE_LOCK: удержание должно переживать переходы в чужое приложение FatSecret. Ключ блокировки не обходится, ACQUIRE_CAUSES_WAKEUP отсутствует, системные тайм-ауты пользователя не меняются. Ожидание ИИ и разблокировки не держит экран. Прототип с флагом окна не прошёл реальную проверку сна и в итог не вошёл.
- Очередь пробуждается по ACTION_SCREEN_ON/USER_PRESENT: отменяется только ожидающий getUpdates, сначала читаются входящие cancel/stop, затем выполняется готовый план. Гонка события с регистрацией poll не теряет сигнал; запросы ПК/записи не отменяются. Частый пятисекундный фоновый опрос не используется.
- 120 JVM и 34 PC-теста прошли, build/lint завершены. На чистом Android 11 с системным минимальным тайм-аутом 10 секунд проверено настоящее удержание экрана, засыпание после снятия и автоматическое освобождение по сроку. Фаза включена в Windows/CI smoke; в ней дополнительно проверяется системное событие включения/разблокировки. Окно сбора голоса использует long-poll до ближайшего срока/45 секунд вместо двухсекундного сетевого цикла; новое сообщение возвращается сразу.
- Настоящий FatSecret в эмуляторе прошёл два маршрута: готовый план при реально погашенном экране без claim, только читающий статус, продолжение после пробуждения/разблокировки до формы; и обычный маршрут с включённым экраном. Оба отменены перед Save. Повтор доставки не исполняет форму снова, исходные дневник/завершённая квитанция сохранены, активного удержания экрана после тестов нет. Новая еда не записывалась. Это проверка Android-маршрута с контролируемым PC-транспортом, физический Realme по-прежнему не подключён.
