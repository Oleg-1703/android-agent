# Помощник ПК по подписке

Claude Code вызывается локальным CLI по существующему подписочному входу. Голос расшифровывается локально faster-whisper. Платные API-ключи не используются; helper отказывается от API-auth.

Android получает сообщения Telegram и отправляет один запрос с описанием, фото и голосом. ПК разбирает его, получает КБЖУ по штрихкоду при необходимости и заполняет **свою еду** в установленном FatSecret на авторизованном Android 11 эмуляторе. Второй Telegram poller на ПК не запускается.

В 0.8.0 Android может выбрать `target=phone`. Тогда ПК возвращает только проверенный `prepared`-план: ADB и `Emulator` не вызываются, эмулятор не нужен. Android Agent исполняет фиксированную форму на своём устройстве и читает полный дневник. На телефоне сохраняется зашифрованный результат; сервер получает квитанцию.

В 0.9.0 при выключенном экране `prepared` сохраняется в зашифрованную очередь, до разблокировки claim не выполняется. Системное событие включения экрана/разблокировки прерывает только текущий ожидающий Telegram poll. Агент сначала получает входящие команды и обрабатывает cancel/stop, затем продолжает очередь. Частого фонового опроса для разблокировки нет. Перед исполнением включается ограниченное удержание тусклого экрана до 120 секунд; после результата оно снимается в `finally`. На этапе ИИ такого удержания нет. Приложение не включает экран и не обходит PIN. `/status` только читает очередь/квитанцию, `/cancel` завершает ожидающие задания без запуска формы и без изменения старого журнала неопределённой записи.

До локального сохранения выполняется однократный `POST /v1/jobs/ID/claim`: `prepared -> executing`. Повторный claim не разрешает запись. `POST /v1/jobs/ID/receipt` принимает результат только уже начатого телефонного задания, повтор квитанции идемпотентен. При перезапуске незавершённое исполнение становится `uncertain`, не новым планом. Потеря ответа не повторяет Save; `/status` повторяет только передачу сохранённой квитанции. `/health` объявляет поддерживаемые исполнители, и новый клиент отказывается отправлять телефонное задание старому серверу вместо скрытого выполнения в эмуляторе.

## Уже подготовленная машина Олега

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/pc-brain.ps1 start
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/pc-brain.ps1 status
```

Инструменты: `C:/Users/Oleg/.local/share/android-agent-tools`. Конфигурация и pairing token находятся вне Git в `brain/config.json`. Helper слушает `127.0.0.1:8766`; существующий HTTPS tunnel предоставляет доступ телефону. `pair` готовит личную страницу привязки. Адрес и код уже отдельно отправлены владельцу по его прямому запросу; в отчёт они не включаются.

Для режима эмулятора нужен работающий `emulator-5556` с сохранённым аккаунтом FatSecret, app APK и test APK одной сборки. Test-исполнитель отказывается работать на физическом устройстве. В режиме телефона ADB, test APK и эмулятор на ПК не нужны: запись делает основной APK на телефоне. Переустанавливать FatSecret или очищать существующий AVD нельзя. Перезапуск helper выполняется только вне активных заданий; tunnel сохраняется, чтобы не менять адрес.

## Данные и выполнение

- В Claude идут выбранные описания и фото, голос - как локально распознанный текст. ИИ не получает пароль, токен Telegram, дерево личного дневника или историю клавиатуры.
- Вызов CLI ограничен структурированным JSON; shell, файловые инструменты, MCP, навыки, hooks и сохранение диалога отключены. Ответ модели не является исполняемой программой.
- Собственные КБЖУ не заменяются каталогом FatSecret. Если цифры заданы на съеденную порцию, они сохраняются как итог порции. Если напечатана основа на 100 г, выполняется пересчёт.
- Явное «найди существующую еду ...» включает отдельный режим: модель передаёт только название, вариант и граммы, КБЖУ читаются с карточки FatSecret. Полностью читается первая страница результатов, требуется одно совпадение полного названия или всех слов с размером/брендом. Пропуск `small` и создание нового продукта в этом режиме запрещены. Остальные страницы глобального каталога не перебираются; неоднозначность или неполное чтение отклоняются.
- Штрихкод проверяется по контрольной цифре. Полные опубликованные КБЖУ читаются из [Open Food Facts](https://openfoodfacts.github.io/openfoodfacts-server/api/); если товара или хотя бы одного обязательного значения нет, запись отклоняется. Публичная база может содержать ошибки, поэтому ответ включает источник и не называет данные измерением.
- Фото блюда без этикетки даёт явно помеченную оценку модели. Calorie Tracker в подключённом ChatGPT умеет хранить готовые записи, но доступного инструмента распознавания изображения у него нет; для этой цепочки он не требуется.

## Надёжность

`POST /v1/log` создаёт задание с устойчивым ID сообщения. `GET /v1/jobs/ID` возвращает сохранённую квитанцию. Повтор того же задания не повторяет запись. Очередь выполняется одним работником. После перезапуска незавершённые задания помечаются неопределёнными и не воспроизводятся автоматически.

Перед созданием своей еды Android сохраняет зашифрованный write intent. После добавления порции сверяется точное изменение дневника. Ошибка до начала сохранения закрывает собственный черновик. Если сохранение могло начаться, автоматический повтор запрещён. UI dump, секреты и изображения дневника не публикуются.

Временный tunnel может сменить адрес после перезапуска; постоянный hostname пока не настроен. Это ограничение настройки соединения, а не повод повторно вводить состав еды.

Адрес вводить вручную не нужно. `scripts/pc-brain.ps1 install-autostart` создаёт задачу Windows `AndroidAgentPcBrainWatchdog` (при входе и каждые 5 минут): она поднимает helper и tunnel, если они упали, перезапускает tunnel, который не отвечает, и при смене адреса отправляет боту сообщение `AA-URL https://<имя>.trycloudflare.com` без звука и закрепляет его (`pc/tunnel_publish.py`; токен бота и chat id берутся из настроек Claude Code, в репозиторий не попадают). Когда ПК не отвечает (нет DNS, отказ соединения, 404/502/530), приложение читает закреплённое сообщение через `getChat` (не чаще раза в минуту), принимает его только от самого бота и только вида `AA-URL https://[a-z0-9-]+.trycloudflare.com`, сохраняет адрес и один раз повторяет тот же запрос. Код сопряжения по-прежнему обязателен. `stop` останавливает и сторожа до следующего `start`; `uninstall-autostart` удаляет задачу.
