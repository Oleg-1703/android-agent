# Исследование интерфейса FatSecret - 15.11.2026

## Что действительно проверено

Установлено и запущено настоящее приложение `com.fatsecret.android`, версия 11.10.0.3 / versionCode 809. APK и ABI/density splits находятся **вне Git**, в локальных инструментах. Источник XAPK - APKPure; подпись проверена `apksigner`, MD5 сертификата `fc5ac0224d38a9a1e3179d7ee4961d5d` совпадает с независимо опубликованной метаинформацией Uptodown. Это локальное исследование, приложение не включается в наш APK и не перераспространяется.

Для ARM64 используется отдельный AVD `Oleg_FatSecret_API30`: Android 11 Google APIs x86_64 с `libndk_translation.so`. Проверен список ABI с arm64-v8a, установка всех трёх APK и запуск. Обычный AOSP AVD из CI остаётся отдельным.

Пройдены начальные экраны на явно синтетическом профиле `Test`, регион Kazakhstan. Никакие параметры Олега не использовались. После настройки приложение показывает предложение создать аккаунт или войти в существующий; закрытие предложения возвращает на предыдущий экран, доступ к дневнику не получен.

**Тестовый профиль удалён до подготовки входа в настоящий аккаунт**, чтобы его параметры не могли смешаться с данными пользователя. В чистой установке проверен путь «I already have an account»: доступен выбор входа по email/member name или через Google. Логин, пароль и Google-аккаунт не вводились. Реальный дневник, поиск и сохранение еды не проверены.

## Наблюдаемые resource ID

| Назначение | ID в `com.fatsecret.android:id/` |
|---|---|
| Начало нового профиля | `registration_lets_begin_text_solid` |
| Вход существующего пользователя | `registration_sign_in_outline` |
| Заголовок выбора входа | `sign_in_title_text` |
| Вход по email / member name | `sign_in_sign_up_with_email` |
| Google-вход | `sign_in_sign_up_with_google` |
| Предложение создать аккаунт | `create_account_title_text` |

Это позволяет распознавать вход, но не даёт оснований придумывать селекторы дневника или записи еды. Часть новых экранов использует Compose без стабильных resource ID. Снимки/деревья только тестовой установки сохраняются локально в `android-agent-tools/fatsecret-ui`, не публикуются.

## Следующий необходимый доступ

Для дальнейшей проверки действий нужен либо Realme с уже открытым аккаунтом FatSecret, подключённый по USB для локального исследования, либо самостоятельный вход Олега в FatSecret на эмуляторе. Пароль в чат не запрашивается. Сначала проверить чтение/навигацию и фактические элементы дневника; реальные записи выполнять только после явного подтверждения. Developer-ключи не заменяют вход в само приложение и не нужны для основного UI-сценария.

Источники дистрибутива/метаданных: [APKPure](https://apkpure.net/calorie-counter-by-fatsecret/com.fatsecret.android/download), [Uptodown](https://fatsecret-calorie-counter.en.uptodown.com/android/download). Поддержка ARM в Google API images: [Android Developers](https://android-developers.googleblog.com/2020/03/run-arm-apps-on-android-emulator.html).
